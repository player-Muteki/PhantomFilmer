> 本文从外部功能出发，逐项列出 13 种 CLI 模式及独立真机桌面端的输入输出、副作用与安全行为。事实源：`main.py`、`app/modes.py` 与 `web_api/server.py`。

## 1. 入口与模式选择

唯一入口是 `main.py`。参数解析在 `parse_args`（[main.py:44](../main.py#L44)），`--mode` 的可选值共 **13 个**（[main.py:48](../main.py#L48)）：

```text
demo status connection-test safety-test follow-test follow-dry-run fixed-demo
basic-flight-test camera follow reid-enroll reid-demo console
```

分发逻辑在 `main()`（[main.py:120](../main.py#L120)）：

- `FOLLOW_MODES = {"follow", "follow-dry-run", "console", "fixed-demo", "reid-demo"}`（[app/config.py:8](../app/config.py#L8)）。
- 属于 `FOLLOW_MODES` 的模式会先 `load_config()` + `prompt_obstacle_enabled()` 询问本次是否开启避障（[main.py:124](../main.py#L124)）；用户取消（回车且非默认值时返回 `None`）则直接 `return 0`。
- 其余模式直接调用对应 `run_*`。
- 任何模式都未匹配时（理论上不会发生），`build_system(use_fake)` + `controller.describe()` 后返回 0（[main.py:188](../main.py#L188)）。

## 4. 关键模式详解

### 4.1 避障询问流程（所有 FOLLOW 模式）

`prompt_obstacle_enabled(default_enabled)`（[app/config.py:48](../app/config.py#L48)）：

- 回车 → 使用配置默认（`obstacle.enabled`，当前 `false`）。
- `y/yes/是/开启` → `True`；`n/no/否/关闭` → `False`。
- EOF/KeyboardInterrupt → 打印“已取消本次运行”并返回 `None` → 调用方 `return 0`。
- 结果通过 `load_runtime_config(obstacle_enabled)` 以**内存覆盖**方式写入 `obstacle.enabled`（[app/config.py:34](../app/config.py#L34)），不修改 `config.yaml`。

### 4.2 `demo`（默认）

`main()` 落到最后一行：`controller = build_system(use_fake=args.fake)` + `controller.describe()`（[main.py:188](../main.py#L188)）。只打印控制台边界说明，不进入输入循环。

### 4.3 `follow-dry-run`（只算不飞）

- 复用 `build_obstacle_modules` + `ArbitrationEngine`，在 Fake 或真实视频帧上逐 tick 计算控制量与避障决策，**不起飞、不发 `move_rc`**。
- 是验证控制量/避障逻辑的推荐前置步骤（[README.md:31](../README.md#L31)）。
- **不保证真机动力学安全**：不模拟 Wi-Fi 延迟、丢包、风、惯性、RC 反馈、真实 ToF 噪声与碰撞。

### 4.4 `camera`（地面 ReID 预览）

`camera` 在连接无人机前准备 YOLO、OSNet 和参考特征，随后只开启视频流与 ReID
调试画面，不起飞、不发送 RC。模型或参考材料无效时直接退出。

### 4.5 `reid-demo`（现场 ReID 跟随）

流程（[app/modes.py:382](../app/modes.py#L382)）：

1. 选择参考照片（`--reference-image` / `--reference-dir` / `--capture-reference`）或档案（`--profile`），照片与档案互斥（[app/modes.py:395](../app/modes.py#L395)）。
2. `build_reid_runtime_config()` 在**内存中**写入参考照片或档案，不写回 `config.yaml`。
3. 连接前 `detector.prepare()` 预加载 YOLO/OSNet 与参考特征（[app/modes.py:433](../app/modes.py#L433)）；失败则不飞行。
4. 检查电量 → 终端输入 `y` 直接授权起飞（不需要先在地面识别到目标）。
5. `FollowSession(initial_target_lock_frames=0, enable_target_search=True)` 进入直接起飞跟随（[app/modes.py:475](../app/modes.py#L475)）。
6. 到达基础高度后可选普通、手动或侧向模式；进入自动飞行后用 `1/2/3` 在普通、侧向、前向之间切换。切换先清零旧模式状态，再连续确认 5 帧 fresh ReID，确认完成后的下一帧才恢复运动。
7. 侧向模式选择较近的 `90°/270°`，前向模式固定为 `180°`；两者绕过自动避障，并在持续丢失 0.5 s 后复用普通三层有界搜索。

### 4.6 `reid-enroll`（建档案）

- 不连接无人机（[app/modes.py:326](../app/modes.py#L326)）。
- 校验每张照片恰含一个人物，提取并平均 OSNet 特征，写入被 Git 忽略的 `data/reid_profiles/<profile>/`（见 [03](03-视觉感知与目标跟随.md) §6）。
- `--overwrite-profile` 允许覆盖同名档案；否则已存在即报错。

### 4.7 `console`（任务级调度器）

- 由 `app/builder.py::build_system` 装配（[app/builder.py:83](../app/builder.py#L83)）：`ConsoleController` + `CommandParser`（本地规则优先）+ `LLMClient`（OpenAI 兼容回退）+ `ConsoleTools`（安全包装工具）。
- 解析结果只映射到 `ConsoleCommand` 六值白名单（[console/commands.py:6](../console/commands.py#L6)）：`GET_STATUS / START_FOLLOW / STOP_TASK / EMERGENCY_STOP / EXIT / UNKNOWN`。
- 底层经 `ConsoleTools._send_safe_rc` 限幅后才 `move_rc`（[console/tools.py:217](../console/tools.py#L217)），**不会把任意文本变成 RC 指令**。
- LLM 未配置密钥时自动退回本地规则（[console/llm_client.py:34](../console/llm_client.py#L34)）。

### 4.8 `basic-flight-test`（真机专用）

- 双重确认后起飞 → 悬停 5 s → 降落（[app/modes.py:222](../app/modes.py#L222)）。
- 不支持 `--fake`：`main()` 中未把 `use_fake` 传给该模式（[main.py:150](../main.py#L150)）。

### 4.9 `status` / `connection-test`

- `status`：连接后读取电量与高度（[app/modes.py:35](../app/modes.py#L35)）。
- `connection-test`：只验证 `command -> ok` 和 `battery?`，不起飞、不开视频（[app/modes.py:58](../app/modes.py#L58)）；真机固定 `192.168.10.1:8889`。

### 4.10 真机桌面端（不属于 CLI 模式）

- Electron main 启动内置 PyInstaller sidecar；sidecar 随机监听 `127.0.0.1` 端口，端口和会话令牌不暴露给 renderer。
- 桌面端只提供连接、预检、内嵌 MJPEG 视频、起降、悬停和手动 RC，不运行 ReID、自动跟随、搜索或自动避障。
- 起飞要求 SDK、有效视频、电量 ≥20%、底部高度和前向 ToF 五项通过；起飞、正常降落与紧急降落均由前端二次确认。
- 手动 RC 后端限幅为 `[-35,35]`，0.4 s 未刷新自动悬停；前进还受 60 cm 前向 ToF 门控，升降受 40/200 cm 边界约束。
- “正常降落”保留连接和视频；“停止并断开”在空中会先降落；真机适配器仍写 `logs/flight_events/*.jsonl` 审计日志。

完整安装与验收流程见 [桌面端真机操作指导书](桌面端真机操作指导书.md)。

## 5. OpenCV 窗口按键

`handle_key`（[control/follow_session.py:1194](../control/follow_session.py#L1194)）：

| 键 | 行为 | 适用 |
|----|------|------|
| `m` | 150 cm 等待界面进入手动；手动中退出并开始 5 帧 ReID 确认 | follow / console / fixed-demo / reid-demo |
| `a` | 等待界面选择普通自动；手动中表示向左横移 | 同上（按当前状态解释） |
| `s` | 等待界面选择侧向跟随；手动中表示后退 | JointBDOE 与侧向模式可用时 / 手动模式 |
| `f` | 等待界面请求前向跟随；手动中表示下降 | JointBDOE 与前向模式可用时 / 手动模式 |
| `w` | 手动前进 | 手动模式 |
| `d` | 手动向右横移 | 手动模式 |
| `r` | 手动上升 | 手动模式 |
| `j/l` | 手动左/右偏航 | 手动模式 |
| `Space` | 立即悬停 | 手动模式 |
| `1/2/3` | 自动飞行中安全切换到普通/侧向/前向模式 | 非手动状态；目标模式必须可用 |
| `p` | 暂停/继续 | 仅 console 模式（`allow_pause=True`） |
| `q` | 停止跟随并降落 | follow / console / fixed-demo / reid-demo |
| `e` | 急停：立即清零控制量并降落 | 同上 |

`reid-demo` 创建会话时 `allow_pause=False`（[app/modes.py:484](../app/modes.py#L484)），因此 `p` 不生效。

到达基础高度后的 `CONTROL_READY` 没有超时或默认分支，只刷新零 RC 并读取原始画面、
电量和高度。手动方向租约为 250 ms；前向 ToF `<=60 cm` 或无效时只拦截 `w`，
不会调用自动避障。`fixed-demo` 初始 `m` 跳过航线，航线中 `m` 安全抢占。

当前实现存在一个生命周期接线缺口：等待界面按 `f` 会返回 `front`，但
`ControlReadyHandler` 尚未把该返回值推进到 `FOLLOW`。在修复前，应先按 `a` 进入
普通自动，再按 `3` 切换到前向模式；不要把初始 `f` 作为真机操作路径。

## 6. 典型调用流程

```bash
# 1) 无真机验证生命周期与目标丢失保护
.venv/bin/python main.py --mode follow-dry-run --fake

# 2) 真机确认（先连接 RMTT-XXXXXX 的 Wi-Fi）
.venv/bin/python main.py --mode connection-test
.venv/bin/python main.py --mode follow            # 按提示选择避障开关

# 3) ReID 档案注册 → 现场演示（详见 03）
.venv/bin/python main.py --mode reid-enroll --profile person-a --reference-dir data/reid_target/现场注册/一组照片
.venv/bin/python main.py --mode reid-demo --profile person-a

# 4) 自然语言控制台
.venv/bin/python main.py --mode console
.venv/bin/python main.py --mode console --fake

# 5) 真机桌面端：安装 CI/Release 中与当前平台匹配的安装包后启动 PhantomFilmer
```

## 7. 已知限制与未验证假设

- **`--lock-frames`**：解析但不生效（[main.py:112](../main.py#L112)，[app/modes.py:425](../app/modes.py#L425)），保留只为兼容旧命令。
- **`demo` 模式**：不进入控制台循环，只打印描述；与“demo=系统描述”语义一致。
- **模式矩阵的“发送 RC”列**：`console` 的 RC 只在跟随任务运行且安全条件满足时发送；普通对话不产生 RC。
- **初始 `f` 未接入 lifecycle**：`_wait_for_control_selection` 能返回 `front`，但 `ControlReadyHandler` 当前只处理 `manual/side/auto`；应使用 `a` 后按 `3`。
- **桌面端不是自动跟随入口**：它与 CLI 生命周期、ReID 和 `ArbitrationEngine` 分离，只提供真机手动控制。

## 9. 不保证的能力

- 任何模式都无法验证真机动力学、避障物理效果或 Wi-Fi 实时性；`follow-dry-run` 只验证软件链路。
- `console` 不承诺正确理解任意自然语言；无法确定时返回 `UNKNOWN`。
- `reid-demo` 不保证目标识别可靠性（受光照、遮挡、换衣等影响）。
