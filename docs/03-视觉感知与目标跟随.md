# 03 · 人物 ReID 与目标跟随

> [返回总入口](README.md) · 上一篇：[02-系统架构与生命周期](02-系统架构与生命周期.md) · 下一篇：[04-搜索避障与运动仲裁](04-搜索避障与运动仲裁.md)

本项目只保留人物 ReID 识别链路。视觉入口 `create_detector(config)` 始终创建
`PersonReIDDetector`，配置中不存在检测器类型开关。

## 1. 端到端链路

```text
参考照片/本地档案
        ↓
YOLOv8n 行人检测 → 人物裁剪 → OSNet 外观嵌入 → 相似度与歧义判定
        ├──接受目标──→ 可选 JointBDOE 全帧朝向检测 → IoU 匹配目标框
        ↓
DetectionResult → FollowController → ArbitrationEngine → 安全限幅 RC
        └────目标丢失────→ TargetSearchController / 安全降落
```

主要源码：

- `vision/detector_factory.py`：唯一检测器装配入口。
- `vision/person_reid_detect.py`：YOLO、OSNet、匹配与调试画面。
- `vision/reid_enrollment.py`：参考照片采集与运行时配置。
- `vision/reid_profiles.py`：本地人物档案保存、加载和完整性校验。
- `vision/jointbdoe_orientation.py`：可选连续朝向角、目标框匹配与圆周滤波。
- `control/follow_control.py`：将目标位置与面积转换为 RC 指令。
- `control/side_follow_control.py`：侧向/前向共用的朝向目标控制器。
- `control/side_follow_logging.py`：朝向模式逐 tick 异步 JSONL 诊断日志。
- `control/target_search.py`：目标丢失后的有界搜索。

## 2. 检测结果契约

`DetectorProtocol` 定义两个方法：

- `detect(frame) -> DetectionResult`
- `draw_debug(frame, result) -> frame`

关键字段：

| 键 | 语义 |
|----|------|
| `found` | 本帧是否接受目标身份 |
| `is_predicted` | 是否复用临时丢失前的位置 |
| `ambiguous` | 最佳候选与第二候选是否过于接近 |
| `center` | 目标框中心 |
| `area` / `area_ratio` | 人物框像素面积及画面占比 |
| `bbox` | `(x, y, width, height)` |
| `similarity` | 最佳候选与参考特征的余弦相似度 |
| `candidates` | 画面内候选人物诊断数据 |
| `visual_objects` | 可选场景物体框，只用于显示 |
| `body_orientation_angle` | 可选 JointBDOE 平滑朝向角，范围 0～360° |
| `body_orientation_raw_angle` | 本帧未平滑朝向角 |
| `body_orientation_detection_confidence` | JointBDOE 人体检测置信度，不是角度置信度 |
| `body_orientation_match_iou` | JointBDOE 人体框与 ReID 目标框的 IoU |
| `body_orientation_latency_ms` | 本帧 JointBDOE 检测、匹配和角度处理耗时 |

控制层只依赖这份契约，不直接访问 YOLO 或 Torchreid。

## 3. 推理与身份判定

1. `UltralyticsPersonDetector` 使用 `classes=[0]` 只检测 COCO person；桌面端当前固定使用 `config.yaml` 配置的 `weights/yolov8n.pt`，构建脚本会下载并校验该文件。
2. 每个人框转换为 RGB 裁剪，交给 `TorchreidFeatureExtractor` 提取 OSNet 特征。
3. 候选特征与参考特征均归一化，点积即余弦相似度。
4. 最佳相似度必须达到 `reid_similarity_threshold`。
5. 最佳与第二候选的差值必须达到 `reid_ambiguity_margin`，否则返回身份歧义且不运动。
6. `reid_temporary_lost_frames` 当前为 0，目标一旦未确认就立即进入丢失处理。

模型通过 `prepare()` 惰性加载。飞行会话在启动摄像头和起飞流程前准备模型；
模型、权重、参考特征或档案校验失败时任务不会起飞。

### 3.1 可选 JointBDOE 朝向角

当前 `vision.jointbdoe_enabled=true`。关闭时不会导入或加载 JointBDOE，普通跟随行为不变；
侧向和前向模式也会因朝向估计器不可用而隐藏。开启后，JointBDOE 在整帧中同时检测人物和连续朝向角；系统只把与 ReID 已接受目标框
IoU 最高且达到阈值的预测附加到结果，并用圆周均值处理 `359°→0°` 跳变。

官方角度约定在当前实拍中为背面约 `0°`、正面约 `180°`、侧面约 `90°/270°`。
模型没有独立角度置信度，系统不会用检测置信度冒充角度置信度。普通
`FollowController` 不读取朝向字段；侧向和前向模式会校验人体检测置信度与框匹配 IoU
后，把角度交给 `SideFollowController`。

## 4. 参考人物来源

运行时必须且只能选择一种来源：

- `vision.reference_images`：配置中的参考照片列表。
- `--reference-image`：单次运行传入一张或多张照片。
- `--capture-reference`：使用电脑摄像头现场拍摄。
- `--profile`：加载 `data/reid_profiles/<profile>/` 本地档案。

每张参考照片必须恰好包含一个人物。系统对各照片中的人物提取特征，取平均后再次
归一化，得到本次目标参考特征。

推荐先注册档案：

```bash
.venv-reid/bin/python main.py --mode reid-enroll \
  --profile person-a-current-outfit \
  --reference-dir data/reid_target/现场注册/一组照片
```

随后运行：

```bash
.venv-reid/bin/python main.py --mode reid-demo \
  --profile person-a-current-outfit
```

## 5. 档案完整性与隐私

每个档案包含：

- `embedding.npz`：归一化外观特征。
- `manifest.json`：schema、预处理版本、YOLO/OSNet 权重哈希、特征哈希和维度。

加载时会校验模型哈希和特征完整性。更换 YOLO、OSNet 或预处理版本后，旧档案会被
拒绝，必须重新注册。档案可关联个人外观，不应使用真实姓名，不应提交或上传；
`data/reid_profiles/` 已被 Git 忽略。

## 6. 跟随控制

`FollowController` 根据 ReID 人物框生成四通道 RC：

1. 水平误差优先转换为 yaw，不使用横向平移跟人。
2. 人物框占比小于 `target_area_ratio_min` 时前进，大于
   `target_area_ratio_max` 时后退，中间区域保持距离。
3. 垂直误差超过死区时升降。
4. 存在 yaw 或升降修正时降低前后速度。
5. 目标稳定居中并处于距离带内后进入 `LOCKED`；退出使用更宽阈值形成滞回。
6. 最终指令始终经过 `SafetyManager.limit_rc_command`。

当前人物距离带为 0.22–0.32，锁定退出带为 0.20–0.34。真机前必须使用真实人物
视频重新标定，不能直接把配置值视为可靠距离测量。

### 6.1 侧向与前向朝向跟随

两个模式复用同一个 `SideFollowController`，只改变允许的朝向目标：

| 模式 | 朝向目标 | 控制特征 |
|------|----------|----------|
| 侧向 `side` | 自动选择圆周距离更近的 `90°` 或 `270°`；等距时选 90° | 人物偏心时先横移居中且不偏航；居中后等待朝向稳定，再决定是否绕人 |
| 前向 `front` | 固定 `180°`，按圆周最短误差绕行 | 使用同一横移、前后、升降与绕行偏航参数 |

- 初次进入先收集 5 帧稳定角度；角度偏差连续 2 帧超过退出阈值才开始绕行。
- 跑道平移使用人物水平误差，限制为 8～25；绕人横移限制为 10～25。
- 绕人偏航由 `0.80 × 横移量` 前馈与人物中心误差反馈相加，总限幅 30；普通横移阶段不偏航。
- 人物重新居中后等待 5 帧稳定角度，再重新选择最近侧面或确认 180° 目标，避免转身抖动触发反复绕行。
- 侧向模式使用普通/前向距离面积带的 70%（`side_follow.distance_area_scale=0.70`），补偿侧身
  人物框较窄，避免为填满相同像素面积而过近；该比例必须结合真实人物视频重新标定。
- 两种朝向模式按设计绕过 `ArbitrationEngine` 与顶部 ToF 自动避障，但仍执行电量、高度、视频、停止和急停保护。
- 每次模式会话使用 `SideFollowEventRecorder` 写入 `logs/side_follow/*.jsonl`；队列满或写盘失败只丢诊断事件，不阻塞飞控。

自动飞行中按 `1/2/3` 请求普通、侧向、前向模式。切换会清空旧控制器、搜索和检测状态，
先保持悬停，再连续确认 5 帧 fresh ReID；搜索找回目标时也必须完成同样的确认。

## 7. 丢失、重新确认与搜索

- 普通跟随目标丢失后先悬停，达到超时阈值后降落。
- `reid-demo` 启用有界搜索：悬停、必要时有限后退、最后方向偏航、三层完整旋转。
- 侧向与前向模式不再使用独立的横移/旋转恢复控制器；持续丢失达到 `side_follow.lost_confirm_seconds`（当前 0.5 s）后，直接复用同一个 `TargetSearchController`。
- 搜索重新发现目标后必须连续获得配置数量的新鲜、非歧义结果才恢复跟随。
- 手动切回自动同样要求连续新鲜结果，确认期间输出保持为零。
- 模式切换期间若目标丢失，也进入有界搜索；找回后才完成目标模式切换。
- 首次接受目标前，前向避障不会接管 ReID 搜索；这是当前明确的安全边界。

## 8. 能力边界

- ReID 只做外观匹配，不识别真实姓名。
- 换衣、遮挡、俯视、逆光、低分辨率和运动模糊会降低相似度可靠性。
- 多人穿着相近时可能进入歧义保护并拒绝运动。
- 额外场景物体框只用于显示，不参与避障。
- 侧向和前向模式没有顶部 ToF 自动避障，后方、侧方、上方和下方也没有其他传感器保护。
- 基础高度等待界面可按 `f` 直接进入前向跟随；自动飞行中也可按 `3` 安全切换到前向模式。
- Fake 模式生成的轮廓不保证被 YOLO/ReID 接受，只适合验证失败保护和生命周期。
- 真机飞行前必须完成真实人物视频、控制率和完整丢失恢复测试。
