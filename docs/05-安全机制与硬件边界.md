## 2. `SafetyManager` 方法

[drone/safety.py:38](../drone/safety.py#L38)

| 方法 | 行为 |
|------|------|
| `can_takeoff(battery)`（[safety.py:50](../drone/safety.py#L50)） | `battery >= min_battery_takeoff` |
| `should_land(battery)`（[safety.py:55](../drone/safety.py#L55)） | `battery <= low_battery_land` |
| `limit_rc_command(lr, fb, ud, yaw)`（[safety.py:60](../drone/safety.py#L60)） | 每通道 clamp 到 `[-max_rc_speed, +max_rc_speed]` |
| `check_height(height)`（[safety.py:76](../drone/safety.py#L76)） | 只检查 `height <= max_height_cm`；**低离地不再迫降** |
| `update_target_lost(found)`（[safety.py:84](../drone/safety.py#L84)） | 丢失计时：`<hover`→keep，`>=hover`→hover，`>=land`→land；重新发现清零 |

> **事实边界**：`update_target_lost` 的悬停/降落语义主要被旧流程与 `SafetyFeature` 使用；现代主循环 `_loop` 中目标丢失的落地由仲裁的 `lost_land` 路径处理（见 [04](04-搜索避障与运动仲裁.md) §1）。

## 3. 失败收敛矩阵

来源：`FollowSession._loop`（[control/follow_session.py:1783](../control/follow_session.py#L1783)）、`_reach_base_hover_height`（[control/follow_session.py:559](../control/follow_session.py#L559)）、`KernelSession`。

| 故障 | 初始反应 | 计数/超时 | 终态 | 清理 |
|------|----------|-----------|------|------|
| 视频帧丢失 | 零输出 + 重试 | `frame_failure_limit`（30） | `FRAME_LOST_LANDING` | finally 清理 |
| 检测器异常 | 零输出 + 重试 | `frame_failure_limit`（30） | `FRAME_LOST_LANDING` | 同上 |
| 仲裁/feature 异常 | `_kernel._failsafe` 清零 + 重试 | `frame_failure_limit`（30） | `FRAME_LOST_LANDING` | 同上 |
| 底部 TOF 高度无效 | 零输出 + 重试 | `height_failure_limit`（10） | `HEIGHT_SENSOR_LANDING` | 同上 |
| 电量低 | 立即 `_safe_zero_output` | 每 tick 检查 | `LOW_BATTERY_LANDING` | 同上 |
| 超高 | 立即 `_safe_zero_output` | `check_height` | `HEIGHT_LIMIT_LANDING` | 同上 |
| 目标长时间丢失（`lost_land`） | `_safe_zero_output` | 搜索/丢失计时 | `TARGET_LOST_LANDING` | 同上 |
| 避障 5 s 超时 / FAILSAFE | `requires_landing` | planner 超时 | `OBSTACLE_FAILSAFE_LANDING` | 同上 |
| 前向 ToF 连续异常 | FAILSAFE 悬停 | `lost_tof_failure_limit`（5） | 要求落地 | 同上 |
| 手动方向键未刷新 | 独立看门狗清零 | `manual_control.command_timeout_seconds`（0.25 s） | 保持手动悬停 | 无 |
| 手动切回自动 | 连续新鲜 ReID，期间全零 | `manual_control.reacquire_frames`（5） | 确认后下一帧恢复自动 | 无 |
| 自动模式切换 | 清空旧状态并悬停 | 连续新鲜 ReID 5 帧 | 进入 `normal/side/front` 目标模式 | 无 |
| 侧向/前向瞬时漏检 | 立即悬停 | `side_follow.lost_confirm_seconds`（0.5 s） | 恢复则取消计时；持续丢失则三层搜索 | 搜索失败落地 |
| Console 停止超时 | 打印告警 | `task_stop_timeout_seconds`（10） | 强制 `drone.land()` | `_wait_for_session_shutdown`（[console/tools.py:256](../console/tools.py#L256)） |
| 桌面端 RC 未刷新 | sidecar 清零四通道 | 0.4 s | 手动悬停 | 无 |
| 桌面端前向 ToF 无效/过近 | 拒绝正向 RC | 过期 1.2 s / 距离 ≤60 cm | 其他方向仍可操作 | 无 |

> 注：`_reach_base_hover_height` 中高度连续失败也按 `frame_failure_limit`（30）计入（[control/follow_session.py:618](../control/follow_session.py#L618)），与 `_loop` 的 `height_failure_limit`（10）并行。

## 4. 停止 / 急停 / 降落清理

### 4.1 会话内部

- `request_stop()`（[control/follow_session.py:1277](../control/follow_session.py#L1277)）、`request_emergency_stop()`（[control/follow_session.py:1284](../control/follow_session.py#L1284)）。
- 逐 tick：`_emit` 在急停/暂停/停止时折叠为零命令（[control/kernel/session.py:78](../control/kernel/session.py#L78)）。
- `handle_key`：`q` 停止并降落，`e` 急停（[control/follow_session.py:1194](../control/follow_session.py#L1194)）。
- 最终清理：`KernelSession._land_and_cleanup` 顺序见 [02](02-系统架构与生命周期.md) §6。
- 最终清理先清零 RC，再等待前向 ToF 线程停止，避免传感器线程退出期间保留上一条运动命令。

### 4.2 Console 层

- `stop_task()`（[console/tools.py:181](../console/tools.py#L181)）：set `stop_event` → `request_stop` → `_safe_zero_output` → 等待会话结束（超时则强制降落）。
- `emergency_stop()`（[console/tools.py:193](../console/tools.py#L193)）：同上 + `request_emergency_stop`。
- `close()`（[console/tools.py:205](../console/tools.py#L205)）：任务进行中先 `stop_task`，再 `drone.stop()`。

## 5. 硬件边界：Tello vs Fake

### 5.1 真实接口

`DroneAdapter` 抽象（[drone/drone_adapter.py:7](../drone/drone_adapter.py#L7)）：

- 必需：`connect / takeoff / land / stop / move_rc / get_battery / get_height / stream_on / stream_off / get_frame`。
- 可选（基类抛 `RuntimeError`）：`get_yaw`（[drone_adapter.py:42](../drone/drone_adapter.py#L42)）、`get_front_distance_cm`（[drone_adapter.py:46](../drone/drone_adapter.py#L46)）。

`TelloDroneAdapter`（[drone/tello_adapter.py:21](../drone/tello_adapter.py#L21)，唯一导入 `djitellopy`）：

- 固定 `192.168.10.1`（Tello 热点）。
- `takeoff()` 始终要求用户输入 `YES`（或经外层 `authorize_next_takeoff()` 预授权）。
- `get_battery()` 最长 5 s 超时。
- `get_front_distance_cm()` 读“EXT tof?”。
- 可选飞行审计会在每次实际调用 `takeoff()` / `land()` 前后同步写入
  `logs/flight_events/*.jsonl`，包含时间、PID、线程、调用栈、适配器会话与飞行状态。

### 5.2 模拟差异（`FakeDroneAdapter`，[drone/fake_adapter.py:12](../drone/fake_adapter.py#L12)）

| 维度 | 真机 | Fake |
|------|------|------|
| 起飞确认 | `takeoff()` 要求 YES / 预授权 | 直接置 `height_cm = base_hover_height_cm`（配置当前值 150 cm；代码缺省 70） |
| 急停/停止 | `stop()` 清零并关视频 | 只打印“模拟急停”，不改内部状态（[fake_adapter.py:66](../drone/fake_adapter.py#L66)） |
| 电量 | 实时，可读取失败（降级 `None`） | 固定 80%（[fake_adapter.py:31](../drone/fake_adapter.py#L31)） |
| 高度 | 飞控实时，可读取失败 | 起飞/降落直接设定 |
| yaw | 飞控航向 | 由 RC 指令时间积分模拟，回卷到 [-180,180]（[fake_adapter.py:70](../drone/fake_adapter.py#L70)） |
| 前向 ToF | 扩展模块实时 | `front_distance_cm`（可外部注入） |
| 网络/延迟 | Wi-Fi 延迟丢包、视频卡顿真实存在 | 不模拟 |
| 目标丢失 | 光照/遮挡/运动模糊，不可控 | 按 `fake_target_lost_interval_seconds`(12)/`duration`(2) 周期消失（[fake_adapter.py:232](../drone/fake_adapter.py#L232)） |

> **结论**：`--fake` 可验证软件调用链，但**不能证明真机行为一致**（README [README.md:21](../README.md#L21)）。`follow-dry-run` 也不证明真实动力学安全。

### 5.3 桌面端真机边界

桌面 GUI 是旧 WebUI 的基础 Electron 迁移，只覆盖真机手动操作子集。sidecar 复用
`TelloDroneAdapter`，但不进入 CLI 的 `SafetyManager` / `KernelSession` 安全链路；其安全门
位于 `web_api.server` 的本地服务层：

- 起飞前要求 SDK、有效视频、电量 ≥20%、底部高度和前向 ToF 全部可用。
- 四通道限幅 35；前向 ToF ≤60 cm、无效或超过 1.2 s 未更新时禁止前进。
- 高度 ≤40 cm 时禁止继续下降，≥200 cm 时禁止继续上升。
- renderer 每 180 ms 刷新按住的方向；sidecar 0.4 s 看门狗独立清零，窗口失焦也主动悬停。
- 正常降落保留视频与连接；停止/紧急路径关闭连接。桌面端不提供自动跟随或自动绕障。

这些值目前是 `web_api/server.py` 常量，不读取 `config.yaml`；修改 CLI 安全配置不会
自动改变桌面端门槛，维护时必须显式同步并运行 `tests/test_web_api_server.py`。

还需注意：桌面端没有飞行中低电量自动降落或独立底部高度监视；电量/高度主要在前端
每秒请求状态时刷新。升降门只检查最近一次 `_height` 缓存，缓存为 `None` 时当前实现
不会拒绝升降。完整差异、崩溃竞态与交付边界见 [07](07-桌面端架构与安全边界.md)。

## 6. 高度控制细节

- 起飞后闭环到 `base_hover_height_cm`（当前 150 cm），稳定 3 个读数（`base_hover_stable_readings`）后继续（[config.yaml:8](../config.yaml#L8)）。
- `_read_height`：读取原始值 → 有效性校验（`1 ~ height_max_valid_cm`）→ 最近 `height_filter_window`（5）次中位数（[control/follow_session.py:2185](../control/follow_session.py#L2185)）。
- 飞控原始 `h` 只用于状态诊断，不参与升降控制（[README.md:212](../README.md#L212)）。
- 独立离地高度确认（`takeoff_height_verify_enabled`）默认关闭（[config.yaml:13](../config.yaml#L13)）。

## 7. 真机检查清单（非穷举）

1. 先跑 `follow-dry-run --fake` 验证控制量与避障决策（[README.md:31](../README.md#L31)）。
2. 连接 `RMTT-XXXXXX` Wi-Fi，先 `connection-test` 验证 UDP（[README.md:62](../README.md#L62)）。
3. 检查电量 ≥ 20%、净空（后方/侧方/上方/下方顶部 ToF 无法覆盖）。
4. 顶部扩展前向 ToF 起飞前 `prepare()` 失败会禁止起飞；启用避障前确认模块与排线。
5. 随时准备按 `e` 急停。
6. 启用真机 ReID 前必须先完成真实目标视频测试（[README.md:120](../README.md#L120)）。
7. 侧向/前向模式绕过顶部 ToF 自动避障，必须确认全向净空；当前前向模式应从普通自动按 `3` 进入。
8. 使用桌面端时不要同时启动 CLI 飞行进程或其他 Tello 控制软件；单实例锁只防止重复桌面进程。

## 8. 起降飞行审计

`flight_audit.enabled=true` 时，生产装配的真机适配器把事件写入
`flight_audit.log_dir`；桌面端 `RealTelloAdapter` 固定开启并写入 Electron `userData/logs/flight_events`。
事件至少区分 `requested/succeeded/failed`，未连接降落还会记录 `skipped`；写盘失败只打印告警，不阻断起降命令。

审计用于回答“本进程是否调用过起飞/降落 SDK”，不是黑匣子：它不证明飞控收到命令、
桨叶实际状态或物理落地。若飞机已落地而对应会话没有 `land_command/requested`，应优先
排查飞控自动降落或其他控制进程。

## 9. 已知限制与未验证假设

- `check_height` 只做上界检查：低离地高度不再触发自动降落（有意为之，[README.md:209](../README.md#L209)）。
- Fake 起飞直接把高度设为 `base_hover_height_cm`（当前 150 cm，瞬时到位），与真机起飞后闭环渐进爬升不同——**爬升/高度滤波等高度相关逻辑无法通过 Fake 完全验证**。
- 基础高度爬升没有总超时；若底部 ToF 持续返回“有效但偏低”的值，循环会继续请求上升，直到读数到达目标、超过安全上限或出现足够多次读取失败。该阶段的读取失败上限还使用 `frame_failure_limit`，不是 `height_failure_limit`。
- 前向 ToF 只覆盖前向单扇区；1 m 侧移是估算（见 [04](04-搜索避障与运动仲裁.md) §8）。
- 未验证：真实 Wi-Fi 下的控制率、视频延迟、ToF 噪声对安全阈值的影响。
- 飞行审计不是强一致存储；断电、磁盘故障或进程被强杀时可能缺记录。
- 桌面端最后状态来自最近一次成功 HTTP 响应；若物理起飞后、起飞响应返回前 sidecar 崩溃，Electron main 可能仍按地面状态允许重启。任何起飞阶段中断都必须以目视真机为准。
- 桌面端没有 CLI 的飞行中低电量落地、最大高度强制落地或自动避障收敛逻辑；不要把五项起飞预检理解为持续飞行安全监视。

## 11. 不保证的能力

- 不保证 Fake 验证结果代表真机行为；不保证任何硬件安全机制能覆盖所有物理场景。
- 不保证顶部 ToF 能保护非前向方向；不保证 1 m 估算距离准确。
- 不保证在 Wi-Fi 严重延迟下 `min_control_hz` 告警能避免失控——它只是提示。
